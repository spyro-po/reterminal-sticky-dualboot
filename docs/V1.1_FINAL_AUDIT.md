# v1.1.0 final source-release audit

Audit date: 2026-11-05. Runtime/build baseline: `77b9e65` in Draft PR#1.
This audit proposes a **GO for a source-only builder release**, subject to owner
approval. It does not approve firmware redistribution or certify future builds/devices. The later owner report validates the exact artifact below on one device.

## Evidence

The owner reports full Ubuntu Docker Build, Reproducibility Check and Artifact
Verification PASS for `cp-2.0.0-seeedash-1.2.0`. The reviewer did not rerun Docker
locally because no daemon is available. Both supplied local six-file bundles
were independently verified and contain identical firmware segments/fresh images.
Their reports record container context and same-environment reproducibility PASS;
the two files alone are not proof of independently executed compilations.
The retained diagnostics corroborate two successful runs, each with24 recorded
process statuses, including first/repeat drivers; all recorded return codes are0.

The PR baseline's [offline and Docker smoke CI](https://github.com/spyro-po/reterminal-sticky-dualboot/actions/runs/41654498217)
also passed. Smoke CI builds the tools image and runs `list`; it does not compile
firmware. Historical native builds, current offline tests and owner device tests
remain separate evidence. The reviewer performed no device operations. The later [owner report](../manifests/v1.1-hardware-validation.json) records Preserve Data preflight, flash verification, full Flash readback/protected-data verification and 9/9 hardware tests PASS for the exact image below.

## Corrections from the audit

The native Recovery shell block previously continued after a failed vendor
download: a controlled reproduction called a fake flasher even though the fetch
stub returned7. The corrected block enables fail-fast behavior, verifies the
vendor hash/size before erase, and returns7 without calling the flasher stub.
Fresh/Update native blocks likewise stop on failed verification. Documented
backup/readback names now reject existing files, and exact restores check a
saved backup digest and full length. All tests used stubs/private temporary
directories; no real flashing command was executed.

## Remaining warnings and release boundary

No current blocking FAIL remains for the source-only tooling release. The owner reports 9/9 hardware tests PASS for image `e4dcb8…f073`. Windows execution, future builds and other devices remain unverified. Battery power for emergency Up+Reset was not specified; basic sleep/wake passed but stress and held-button wake cases were not reported. Paired writes are not power-fail atomic. All OTA/resource
updates remain forbidden; unmodified Seeedash has unrestricted raw Flash access.
SHA-256 is not authenticated Secure Boot. Seeedash redistribution rights and
combined-binary compliance are unresolved, so firmware/prebuilt-image publication
remains **NO-GO**. The audited hash is a local build identity, not a portable
expected hash for every host. Recovery commands are reviewed procedures, not
newly executed factory/device recovery tests. The owner reported verification of a Preserve Data update, not a factory recovery.
The generated fresh-image hash identifies the build/code pair; it is not the
expected digest of a device readback containing preserved personal data.
